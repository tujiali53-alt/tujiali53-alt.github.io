# 校招作品集网站优化建议

评估日期为 2026 年 11 月 27 日。评估以更新后的本地源码、链接和资源检查为准，覆盖首页、作品页、关于页、简历页和 DOTS 项目详情页。排序依据是招聘方能否快速判断岗位匹配度，以及面试官能否进一步核对个人贡献和项目结果。浏览器布局、线上播放和加载耗时有待实测。

## 目前的优点

- **客户端开发方向有具体项目支撑。** 首页把 MMORPG 和 DOTS 放进精选区。MMORPG 写出了背包、商城、装备、任务以及事务回滚等具体工作，DOTS 说明了从动画烘焙工具到 ECS 系统、Shader 的个人开发范围。面试官有明确的技术问题可追问。
- **实习经历有工作量和验收证据。** 首页和简历写明了 Lua 到 C# 的迁移背景、79 条 Buff 配置和 11 条主动配件技能，也交代了用哪些手段验证行为和排查回归。
- **作品题材和展示方式比较丰富。** 五款 Game Jam 作品覆盖养成、叙事解谜、多结局探索等方向，多数作品配有玩法介绍。作品页还有 VR 家居漫游、三维手语和实验室项目，可以按岗位选择素材。Game Jam 视频均有 B 站原始页面入口，部分作品还有赛事或作品页面。
- **已有从了解候选人到查看简历的路径。** 首页提供作品和简历入口，作品页有分类目录，桌面和移动端都有导航。关于页补充了从测绘到 Unity 开发的学习经历，并提供邮箱和 GitHub 入口。
- **网站有个人辨识度，也有部分性能和易用性基础。** 首页肖像插画、作品页的视觉风格和关于页照片提供了个人表达。首页主要图片已使用 WebP，关于页相册已有图片懒加载，CSS 和 JavaScript 也处理了减少动态效果的系统偏好。

## 目前的不足

- **首页新增的四个方向还没有对应的证据入口。** 首屏品牌和网页版简历仍以 Unity 客户端开发为主。投游戏策划、游戏制作人或 VR 开发岗位时，招聘方需要自行在长作品页里寻找相关项目，才能判断哪些经历与岗位匹配。
- **Game Jam 页面主要介绍团队作品和剧情，个人贡献仍难核对。** 目前各卡片没有统一交代个人角色、负责模块、关键决策或交付结果。《阿卡夏启示录：愚者的朝圣》目前有作品名和演示视频，玩法简介与赛事名称还待补齐。VR 家居漫游也只简述了项目主题。
- **DOTS 详情页是首页的直接入口，仍存在公开的占位内容。** 详情页展示占位图和待补充的测试说明，作品页也显示 GitHub 地址待补充。标题提到上万实体，目前页面未给出设备、实体数、帧耗时和对照方案，招聘方无法从页面核对性能表现。
- **简历路径有版本与操作文案需要核对。** 首页写着“查看并下载简历”，实际先进入网页简历，PDF 入口在页面末尾。仓库根目录和 `docs` 内有两个哈希不同的 PDF，需要确认投递时采用哪一份，以及网页和 PDF 的关键信息是否一致。
- **作品页有清晰分类，定位到具体项目还需要额外滚动。** Game Jam 已扩展到五款作品，目录只能跳到分类开头。首页比赛区和简历提到参加过三次 21 天 Game Jam，作品页又收录了其他赛事，招聘方可能将两者误读为同一个统计口径。
- **作品页有可确认的加载负担。** 实验室相册将同一批原图用于大图和缩略图，引用了约 11.60 MiB 的 `lab-07.jpg` 和 3.29 MiB 的 `lab-06.jpg`，相关图片目前未标记懒加载。作品页有 10 个 B 站视频位，共用的播放器脚本在初始化时就给每个视频位创建 iframe，也发起封面请求。实际传输量和加载时间需要用冷缓存和慢网速建立基线。
- **异常情况下的访问、键盘体验和分享信息还需完善。** 全页加载遮罩依赖 JavaScript 关闭。导航淡出后的浏览器返回行为需要跨浏览器复测。多数页面缺少跳到正文的链接，通用图片弹窗的焦点行为仍需用键盘走查。各页有标题和描述，尚未配置独立的分享图和 Open Graph 元数据。

## 优化任务与验收标准

按表中序号推进。同一优先级内先处理上方任务。P0 优先解决投递时的岗位表达、作品证据与入口，P1 提升查阅速度和稳定性，P2 完成发布和维护细节。

| 顺序 | 优先级 | 任务 | 验收标准 |
| --- | --- | --- | --- |
| 1 | P0 | 清理 DOTS 详情页的占位图、编辑提示和未提供的 GitHub 入口，并核对「上万实体」的表述。 | 从首页进入详情可以看到有效的项目说明和播放入口。页面中的规模和性能表述有已验证的依据。 |
| 2 | P0 | 整理校招意向和首页证据入口。按实际投递岗位明确首屏主方向，并为 Unity 客户端、策划、制作人和 VR 开发选择对应的代表作品。 | 招聘方打开对应投递链接后能看到该岗位和一项具体经历。作品入口可直达对应项目，网页简历的意向和本次投递一致。 |
| 3 | P0 | 给五款 Game Jam 和 VR 家居漫游补个人贡献。优先整理计划投递时使用的两款游戏，并补齐《阿卡夏启示录：愚者的朝圣》的玩法简介和经确认的比赛名称。 | 每个代表项目写清团队规模、开发周期、个人角色、负责模块和一项具体交付。策划用规则、关卡或迭代记录举证，制作人用排期和交付举证，开发用功能或实现举证，VR 写清设备与交互范围。 |
| 4 | P0 | 补齐两个客户端项目的面试材料。DOTS 记录测试设备、Unity 版本、实体规模、CPU/GPU 帧耗时和对照方案，MMORPG 展示框架边界以及个人实现的事务和回滚流程。 | DOTS 有真实运行截图和至少一组同条件对照数据。MMORPG 有一张可解释的交易流程图或一段可公开的实现示例。两项都有可打开的演示视频。 |
| 5 | P0 | 确认唯一的正式投递 PDF，把下载入口放到网页简历顶部，并审核公开 PDF 的版本和联系方式。 | 从首页进入简历后可以直接下载。正式 PDF 和网页版的求职意向、日期、项目和联系方式一致。对外分享链接指向确认过的版本。 |
| 6 | P0 | 验证投递链接和视频回退。在发布环境用未登录浏览器打开首页、简历、PDF、代表作品锚点及 B 站演示。 | 桌面及目标手机浏览器都能走通首页到作品和简历的路径。播放器受限时，作品说明和 B 站直达链接仍能使用。 |
| 7 | P1 | 缩短作品页的查找路径。为五款 Game Jam 增加目录内的项目直达入口，并在首页或比赛区链接最相关的 Game Jam 与 VR 代表作。 | 手机端可从目录直接跳到项目标题，固定导航不会遮住标题。「三次 21 天 Game Jam」和其他赛事的收录范围表达清楚。 |
| 8 | P1 | 减少视频初始化开销。用可公开的本地封面和播放按钮作为初始状态，收到用户操作后创建 iframe，同时保留 B 站原始链接。 | 冷缓存进入作品页时没有播放器 iframe 请求。鼠标点击、触屏操作和键盘操作都能触发对应视频。 |
| 9 | P1 | 压缩实验室和相册图片，生成独立缩略图，给非首屏图片添加懒加载和尺寸信息。 | 缩略图使用小尺寸文件。对比同一视口、网络和缓存条件下的修改前后请求数与首屏传输量，并检查画廊浏览和放大效果。 |
| 10 | P1 | 让正文默认可访问。调整加载遮罩和导航过渡的初始化方式，复测禁用 JavaScript、脚本加载失败以及跨页返回。 | 禁用 JavaScript 或脚本加载失败时，正文与普通链接可使用。Chrome、Edge 及目标移动浏览器从作品页返回首页时能正常显示。 |
| 11 | P1 | 检查移动端首屏和键盘阅读。优先调整作品与简历按钮的位置、标题层级、正文对比度以及弹窗的焦点管理。 | 在 360 px 和 390 px 宽度下，首屏能快速找到两个投递入口。键盘能跳到正文、定位播放按钮、关闭弹窗并回到触发点。 |
| 12 | P2 | 完善分享与维护信息。添加网站图标和分享卡片，把关于页的 B 站搜索链接替换成确认过的个人空间，更新内容维护指南。 | 在常用聊天工具中实测首页和代表作品的分享效果。B 站入口直达个人空间，维护指南与实际项目卡片、视频和简历路径一致。 |

本次已完成首页标签和三款 Game Jam 作品的补录。表内任务供后续逐项实施，其中作品职责、测试数据、公开材料和简历版本需要以本人确认的事实为准。
